### One to Many

A One-to-Many relationship means:
    One object/row in a table can be related to many objects/rows in another table.

One-to-Many means one record in one table can relate to multiple records in another table.

Department
----------
dept_id | dept_name
1       | Computer Science

Employee
--------
emp_id | name  | dept_id
1      | Ravi  | 1
2      | Asha  | 1
3      | Manoj | 1

Hibernate Example

### Example classes:

1. Department
@OneToMany
List<Employee> employees;

2. Employee
@ManyToOne
Department department;


3. Relation
Department
   |
   |---- Employee
   |---- Employee
   |---- Employee

meaning one dep can have many employesss
and employee belongs to only one Department

In the database:
    The foreign key is always stored on the "many" side.

### Hibernate relationships naturally work with:

✅ List
✅ Set
✅ Collection

NOT arrays.

Because ORM tracks collection changes.

So always think:

Entity relations → Collections, not arrays.


### Cascade means:

When I perform an operation on Parent,
automatically perform the SAME operation on Child.


Real Meaning

You have:

Programmer  --->  Laptop
(parent)          (child)

If you save Programmer…
Should Hibernate also save Laptops automatically?
👉 Cascade decides this.

Without Cascade

You must manually save everything.

session.persist(laptop1);
session.persist(laptop2);
session.persist(programmer);

With Cascade

session.persist(programmer);

Hibernate internally does:

persist(programmer)
    ↓
persist(laptop1)
persist(laptop2)

## Another Problem 

Hibernate tracks entity state per session.

Once session closes:

It forgets everything.

So in second session:

l2 is considered transient again.

Hibernate doesn’t check DB before insert.
It assumes you know what you're doing.
