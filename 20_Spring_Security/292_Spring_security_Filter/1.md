Spring Security Filters are also servlet filters. The difference is who created them and what they do.

They're just implemented using Java Servlet Filters and organized into Spring Security's filter chain.

### Easily confused

Request
   ↓
Servlet Filters        <-- Before Spring MVC (Spring Security lives here)
   ↓
DispatcherServlet
   ↓
Interceptors           <-- Around controller execution
   ↓
Controller

Filters: Work at the servlet level. Good for authentication, logging, CORS, compression, etc.
Interceptors: Work inside Spring MVC, after a request has been matched to a controller.
AOP: Works around method execution (services, repositories, controllers), not HTTP requests directly.

Each filter has one responsibility:

Read the JWT or session
Authenticate the user
Check CSRF
Verify roles/permissions
Continue to the next filter

### One small caveat

In Spring, there are three layers where you can intercept execution:


Client
   │
Servlet Filter        ← Middleware (HTTP level)
   │
DispatcherServlet
   │
Interceptor           ← Spring MVC level
   │
Controller
   │
Service
   │
AOP                   ← Method level
