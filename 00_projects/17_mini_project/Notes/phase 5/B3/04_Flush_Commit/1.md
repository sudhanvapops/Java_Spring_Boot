### Flushing

Flushing is the process of synchronizing the state of the persistence context with the underlying database.


exectues the Pending SQL Statements on the DB connection
The changes are not permanent and are not visible to concurrent Transactions



Flushing Stratergies in HIbernate:

ALWAYS
      Flushes the Session before every query.

AUTO (is in JPA)
      This is the default mode and it flushes the Session only if necessary.

COMMIT (is in JPA)
      The Session tries to delay the flush until the current Transaction is committed, 
      although it might flush prematurely too.

MANUAL
      The Session flushing is delegated to the application, which must call Session.flush() explicitly in order to apply the persistence context changes.

### Outside the Transaction Boundry


public void changeTitleOutsideTransaction(Long id) {
    Book book = bookRepository.findById(id).orElseThrow();

    book.setTitle("Changed Outside Transaction");

    // NO save()
}


findById() runs inside a temporary repository transaction/persistence context.
During that operation, book is managed.
When that transaction ends, the persistence context closes → book becomes detached.
Then book.setTitle(...) only changes the Java object in memory.
Hibernate is no longer tracking it, so no dirty checking → no UPDATE.
