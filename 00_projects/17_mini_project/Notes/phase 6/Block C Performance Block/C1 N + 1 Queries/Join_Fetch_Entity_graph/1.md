### Mental Model

All Lazy and Fetch 
sets a default FETCH Plan
The same for every query 

the demand wont meet for a specific endpoint causing 1 + N Query problem


## FETCH JOIN

A fetch join overrides the default for a single query: 
    for this query, load these associations in the same SQL statement

so now instead of N + 1 trips we have 1 trip

so after data arrived
example: book.getAuthor() wont cost a qury since it is already in the Persistance context


Write your own Join query in JPQL

@Query(
        value = """
            SELECT br FROM BorrowRecord br
            JOIN FETCH br.borrowTransaction bt
            JOIN FETCH bt.member m
            JOIN FETCH br.book b
        """,
        countQuery = "SELECT COUNT(br) FROM BorrowRecord br"
    )
List<BorrowRecord> findAllWithAssociations(Pageable pageable);

### Enitty Graph

declarative, attached to a repository method. 
It lists the paths to fetch, and the query itself can stay simple or derived.

@EntityGraph(attributePaths = {"borrowTransaction", "borrowTransaction.member", "book"})
@Query("Select br from BorrowRecord br")
List<BorrowRecord> findAllWithGraph();
